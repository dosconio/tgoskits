## 三、分步实施计划

### 第 3 步：PCI 主桥（PIO 方式）— 让 OVMF 能扫描总线

**目标**：实现 `0xCF8`/`0xCFC` 的 PCI 配置空间模拟，OVMF 扫描 Bus 0 时能看到 PCI 主桥和后续的 virtio-blk 设备。

**实现要点**：
- 新建 `components/pci_host/` crate
- `PciHostBridge`：维护 `config_address: u32`（0xCF8 写入值）+ PCI 设备列表
- `PciConfigSpace`：每个设备 256 字节配置空间
- 注册为 Port I/O 设备（0xCF8~0xCFF）
- PCI 主桥自身在 Bus 0/Dev 0/Func 0 暴露（Vendor=0x8086, Device=Q35 MCH）
- 暂时只实现 PIO 方式，ECAM 后续再加

**验证**：OVMF 启动后日志显示扫描到 PCI 设备

### 第 4 步：最小 virtio-blk-pci — 让 OVMF 能发现磁盘

**目标**：实现一个最小可用的 virtio-blk-pci 设备，OVMF 能通过 PCI 枚举发现它并尝试引导。

**实现要点**：
- 新建 `components/virtio_pci/` crate（virtio-pci 框架 + virtqueue）
- 新建 `components/virtio_blk_pci/` crate（virtio-blk 特有逻辑）
- `VirtioPciDevice`：PCI 配置空间 + Common/Notify/ISR/Device-specific MMIO BAR
- `VirtQueue`：Descriptor Table + Available Ring + Used Ring
- `VirtioBlkPci`：处理 read/write 请求，后端对接文件系统中的磁盘镜像
- 注册到 PCI 主桥的设备列表
- BAR 地址分配（在 MMIO 区域中预留一段给 virtio-pci BAR）

**验证**：OVMF 发现 virtio-blk 设备，尝试从中读取 EFI 分区

### 第 5 步：vIOAPIC + 基本中断链路 — 让中断跑通

**目标**：实现虚拟 IOAPIC，连通设备中断 → vIOAPIC → vLAPIC → VM-entry injection。

**实现要点**：
- 新建 `components/x86_vioapic/` crate
- IOAPIC MMIO 寄存器模拟（0xFEC00000 区域）
- 24 个 RTE（Redirection Table Entry）
- 中断路由：RTE 指定 target vCPU + vector
- 连通 vLAPIC：vIOAPIC 产生中断 → 调用 vLAPIC 的中断注入方法
- 修复 `inject_interrupt()` 空函数
- virtio-blk 的 INTx 中断通过 vIOAPIC 注入

**验证**：OVMF 的 UEFI Shell 能正常启动，virtio-blk 中断能正常触发

### 第 6 步：ECAM + 完善 + 冒烟测试

**目标**：补齐 ECAM 方式 PCI、vLAPIC 关键功能，建立完整验证闭环。

**实现要点**：
- ECAM MMIO 模拟（`0xB0000000` 区域，MCFG 表已声明）
- vLAPIC EOI 广播（连接 vIOAPIC）
- vLAPIC INIT/SIPI（SMP 启动）
- vLAPIC Timer 中断
- 编写 QEMU 冒烟测试配置
- 验证路径：OVMF Shell → Linux EFI stub → 内核启动

## 四、"先让 OVMF 跑起来"的最小路径

最快让 OVMF 进入 UEFI Shell 的精简路线：

```
第 3 步（PCI PIO 主桥）→ 第 4 步（virtio-blk-pci 最小实现）→ 第 5 步（vIOAPIC）
```

- **第 3 步**必须：OVMF 启动后一定会扫描 PCI 总线
- **第 4 步**必须：OVMF 需要发现磁盘才能继续引导
- **第 5 步**可延后做极简版：OVMF 在没有中断的情况下也能进入 Shell（设备操作会超时但不会崩溃）

**真正的最小路径是先做第 3 步 + 第 4 步**，让 OVMF 至少能扫描到设备并尝试交互，即使中断不通也能看到 UEFI Shell 提示符。
